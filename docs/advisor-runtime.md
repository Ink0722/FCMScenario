# 真实 Advisor：本地材料联调

文档整理：2026-11-05（北京时间）。实现保留案例 PDF、策略提交和流式回复的 Advisor 接口；当前正式案例为空，Advisor 只能在新案例审核并登记后进行材料沙盒验收。验证记录与费用以持久化账本为准；无公网搜索、托管检索或云端计算。正式研究目标及 Prompt 审核、PostgreSQL 并发和部署验收仍独立进行。

## 使用

1. 同时启动 API、Worker 和 HTTP 模式前端，见 [后端说明](../backend/README.md)。更新执行器代码后重启 Worker。
2. 控制台 → 设置 → 可选模型。GPT 预设为 `gpt-5.4-mini-2026-03-17`、`https://api.openai.com/v1`；API Key 在此填写并保存。已保存的 Key 留空保留，不回显。保存不调用模型。
3. 点击“验证 Advisor”，创建独立持久化作业，不创建参与者。Worker 用案例 01 验证完整协议，页面自动查询；丢失受理响应后沿用同一请求编号。刷新或读取状态不发起新模型调用。
4. 通过后创建新的发码预览或配额方案，整批选该模型，即可发放。选择“不使用模型”仍走确定性回复。旧预览不追溯开放，旧批次也不跟随设置变更。

验证绑定冻结连接（含加密凭据）及完整运行配置摘要。Prompt、策略目录、工具参数、SDK 适配版本、接口或凭据变化后，新预览需重新验证。一次连接短句验证不能替代 Advisor 验证。首版仅开放核价的 GPT 预设，不自动切模型或降级。

## 协议与输入

每轮由同一 Advisor 执行准备 → 本地资料工具 → `select_strategy` → 正式回复。工具只读当前案例的冻结公开 PDF，按 document ID、内容摘要和页码校验，不接受任意路径或外部 URL。

- `read_material`：每次最多 3 页、18,000 字符，包含原始页码、截断和文本可用状态。
- `search_material`：按材料语言的中英文关键词检索，最多 3 个页片段、每片段 4,000 字符；没有 OCR、语义检索或外部检索。PDF 按 SHA256 和解析器版本缓存为校验后的派生工件，优先保留表格布局；源文件改变会拒绝旧缓存。未命中不代表不存在相关事实。
- `select_strategy`：只接受当前目录中的一个 ID。现行英文目录为 S00、S01–S10、S14，来自 [Notion ToolBox](https://app.notion.com/p/4083854bbee98128a55ff516d725fdec)，包含 definition、boundary 和 execution_prompt；可选参数随目录生成，冻结源和版本。正式回复前先提交；无效/重复策略或不合协议的工具调用中断并保留证据，不补造 S00。

每轮最多 4 次模型生成、2 次材料调用；第三次模型调用仍在准备时强制提交策略，保留第四次生成正式回复。资料不足须说明限制。正式回复关闭全部工具；准备文本、工具结果、原生摘要及策略只供研究者回放，不进入参与者公共快照。

模型输入白名单包括公开案例、实际展示顺序、完整策略目录和当前 attempt 的对话/工具历史。Goal 额外包含固定目标，Neutral 不发送后台比较目标。Profile、前测/最终判断、研究者 Notes、研究参考答案和其他人的数据不进入模型。重做产生新 attempt 并隔离上下文。使用完整手动历史、`store=false`，不依赖供应商保存的会话或 `previous_response_id`。

Prompt、完整工具 JSON 和目录分别维护于 `backend/config/advisor-prompt.json`、`advisor-tools.json`、`advisor-toolbox.json`，发布预览时冻结私有工件。Native reasoning 使用 medium，summary=auto；只保存实际返回的摘要，未返回标为 not_returned，不事后生成思维过程。依据 [OpenAI 官方推理与无状态历史说明](https://developers.openai.com/api/docs/guides/reasoning) 保留已完成的 encrypted_content，重放时移除 SDK 未设置的空字段并使用协议字段别名。准备/正式回复的阶段指令只放在当前请求 instructions，不写入长期历史；旧历史中的阶段 developer/system 指令在读取时剔除，实际供应商输出与工具结果保留。

## 控制台编辑提示词

研究控制台 → 提示词，可直接编辑七项对话文本：共同规则、Neutral、Goal、准备阶段、正式回复、开场白和材料使用规则；另外可编辑当前策略卡的名称、定义、分类边界、执行提示词，以及三个工具的说明。Goal 必须保留 `{target}`。策略编号、工具名、参数结构、材料权限、调用次数和费用上限由代码控制，不通过文字编辑器修改。

JSON 文件提供部署默认值；控制台保存的文本在 `system_jobs.kind=advisor_text_settings` 中持久化，优先用于新配置，不回写代码文件。每次保存保留文本版本和审计，使用 revision 防止并行编辑覆盖，requestId 保证响应丢失后的重试不重复修改。页面支持未保存提醒、单项恢复文件默认值、撤销草稿与 JSON 导出；未确认保存可在同一标签页刷新后继续查询。保存不调用供应商。

模型连接冻结时，同时冻结本次读取到的完整 Advisor 运行版本，普通预览、配额预览和 Advisor 验证均使用同一工件，避免读取设置后再冻结时混入另一版本。文本变化后，现有模型的验证状态会针对新版本重新计算；重新验证后才能发放该新版本。已创建的预览、批次、进行中的任务继续使用原冻结版本。旧冻结配置缺少 prepare 字段时保留原阶段指令，继续可执行。

## 额度与网络

连接验证及全部 Advisor 准备/正式回复共享部署累计 **$1**。整数 nano-USD 账本保存在 system_jobs；更换模型、保存设置、重启或删除测试参与者均不重置。按固定版本已核对价格保守结算，缓存折扣不提前用于授权；不限制同一 Key 在其他应用的消费。

Advisor 每次付费请求前用[官方计数接口](https://developers.openai.com/api/docs/guides/token-counting)核算完全相同的输入、工具及指令，然后按输入与最大输出预占。每次最多输出 1536 Token，包含推理与格式 Token。预占事务成功后才发送，余额不足提前中断；旧连接验证的完整上下文预占仍计入总额。收到匹配型号、有效用量后结算，超时或用量未确认保留预占。供应商调用关闭自动重试、自动重定向，使用系统代理配置且保留 TLS 校验。

当前结算、预占和剩余额度以设置页账本为准。研究者可凭供应商已确认记录核对旧预占；无法确认时继续保留，不能通过删除参与者、更换连接或重启来重置额度。

## 持久化与恢复

- 作业类型：advisor_turn、advisor_validation；每次供应商请求另记 advisor_model_call。后者即使参与者取消也保留费用和请求证据。
- 领取/检查点使用短事务，真实 SDK 网络调用在事务外。PostgreSQL 使用事务锁，SQLite 使用 BEGIN IMMEDIATE；全部署同时最多一个 Advisor 作业，租约 90 秒。Worker 心跳线程独立于模型网络调用。
- 同一消息受理防重；刷新、重连和回放只读原运行，不新建付费调用。租约到期中断运行，不能照搬确定性 Worker 的自动重算恢复。系统不承诺供应商副作用严格恰好一次。
- 每个实际请求保存私有 requestRef、供应商请求/响应 ID、原始输出工件、用量、费用、耗时与摘要状态；每个工具保存参数、结果和状态。部分正式文本以相同消息 ID 持久化，流中断保留部分回复及费用预占。
- 放弃、取消或到期后，旧作业失去更新当前对话的资格。迟到的费用证据可保存到旧轮次，但不能推进新尝试。仅完整回复保存后计入轮数；仍为最少 3 轮、默认最多 20 轮。

控制台任务页回放实际记录；设置页分页显示全部模型调用及连接验证的用量与费用。满 5 分钟且未确认的费用可凭供应商证据核对，输出上界按原请求校验。回放不调用模型。原生摘要不是逐 Token 思维记录；未返回的摘要不推断。

## 验证

后端使用实际 OpenAI SDK 和 Responses SSE 的离线传输，覆盖上下文白名单、本地 PDF 与中文检索、策略先提交、三轮流程、重复受理、旧预占与额度阻断、流中断、Worker 租约失效、取消后的迟到结果。HTTP 浏览器测试使用隔离数据库和离线供应商传输，覆盖验证响应丢失/刷新恢复、验证后发码、公共 SSE 与后台回放。另执行真实案例 01 沙盒验证上述供应商协议，不把离线桩记入真实账本。


## 本轮完善

- 普通发码在首次冻结后保留 configRef；未确认请求保存在当前浏览器标签页的 sessionStorage，刷新后仍按原编号/正文重试，不重新预览。原发放回执优先恢复，即使设置改变、额度不足或访问期限已过也不另建一批；新的过期发放仍拒绝。
- 队列告警结合 Worker 心跳、当前作业租约和执行进度。正常长回复及其后的排队不因创建时间超过 30 秒而误判卡住。
- 发码与配额发放共享服务端额度预检。按最低轮数×个人任务数×每轮参考费用估算，每轮至少 $0.03，近期实际运行费用更高时采用更高值。它不是预占或费用保证，其他任务和上下文会影响实际支出；逐请求 $1 账本仍是强制上限。参考余额不足则不创建新真实批次，确定性发码继续可用。
- 设置可选择当前已审核并登记的案例、Neutral/Goal、Goal 的 A/B 目标、1 或连续 3 轮独立沙盒。当前没有正式案例，Advisor 验收入口会保持禁用；新案例接入后再按案例和条件逐项验收。
- 引用只在文档 ID、页码确实出现于已提供的工具结果时生成链接。参与者链接按当前授权签发短期票据并定位页码；后台按任务归属读取同一冻结材料。引用不匹配保留原文本并记 citation_warnings，不伪造来源。此检查证明来源页已提供，不等于该页支持回复的每个断言。
- 后台执行轨迹以表格显示阶段、耗时、Token、费用、原生摘要和工具，原始 JSON 折叠保留。参与记录可下载 [研究数据 ZIP](research-data-export.md)，费用按当前账本补齐，包括费用登记后检查点前中断的请求。
- 离线验收应覆盖当前已审核案例及其材料作用域；当前无正式案例，因此不生成旧案例审计报告。新案例接入后，再运行材料审计并记录提取页和数字行样例。

## 连接验证与配置冻结

`python -m backend.app.cli configure-openai` 追加已支持的固定 GPT 预设。设置可以维护多个独立连接；保存配置不调用供应商，旧单模型设置读取时兼容为注册项。接口地址、模型名、加密凭据和运行版本在预览时冻结，后续编辑或移除注册项不改写既有批次。

“验证连接”发送固定英文短句，不读取参与者、Profile、测量或案例；该入口最多输出 128 Token，并按完整上下文上界及输出上限预占费用。它与完整 Advisor 验证共用部署累计预算，计价与预占参数以 `backend/app/model_runtime.py` 为准。

连接验证仅证明该请求可用。完整 Advisor 验证检查策略、工具和正式回复协议，成功后仅允许相同连接、凭据和运行版本的新预览发放。不能将未就绪的真实模型配置静默替换成确定性回复，也不能自动换 Key 或模型。

用量未确认的记录登记满 5 分钟后，研究者可在设置页填写供应商记录编号、输入/输出用量与核对依据。后端串行结算并留审计，同编号重试不重复结算，已结算记录不可改写。计数与费用缺失保持缺失，不按零处理。

正式研究仍需审核案例目标、Prompt / ToolBox、语言和分析口径；新增供应商或托管工具需另做能力、预算与失败方式验收。当前数据库 Worker 和本地 PDF 工具不代表已经实现 Redis/Celery、公网检索或托管计算。
