# 可选模型与真实 Advisor 接入方案

更新时间：2026-10-20（北京时间）。下文保留原阶段规划；当前本地材料首版已实现，真实连接验收和精确运行约定以 [Advisor 运行说明](advisor-runtime.md) 为准。旧版“未接入”表述描述规划时状态。完整研究运行协议沿用 [后端设计](backend-design-proposal-2026-10-19.md)，并保留当前确定性运行作为独立可选模式。

## 首个真实连接与 1 美元限制

预设为 GPT-5.4 mini，固定版本 `gpt-5.4-mini-2026-03-17`，Base URL 为 `https://api.openai.com/v1`。按 [OpenAI 官方型号文档](https://developers.openai.com/api/docs/models/gpt-5.4-mini)（2026-10-20 核对），支持流式、函数调用和结构化输出；标准文本输入 $0.75 / 百万 Token、输出 $4.50 / 百万 Token。固定版本便于复现。账户实际访问权限须在填写 Key 后验证。

执行 `python -m backend.app.cli configure-openai` 可追加预设，保留现有模型、密钥和所有额度记录。研究者在“设置 → 可选模型 → GPT-5.4 mini（联调）→ API Key”填写并保存；密钥仅在后端解密。保存不会调用供应商。点击“验证连接”才发送一条固定英文短句，不读取参与者、Profile、判断或案例。

后端对本部署的供应商请求设置 **累计 $1** 上限，并非每次、每天或每批 $1。当前唯一外部执行入口是这个受保护的连接验证，使用 Responses API、标准服务档位、纯文本、无托管工具、最多输出 128 Token（包含推理 Token），关闭响应持久化及自动重试/重定向。其他接口、型号、第三方地址暂不开放实际调用。

额度账本保存在 `system_jobs.kind=model_connection_probe`，整数 nano-USD 计费。每次先按完整 400,000 Token 上下文上界及最大输出预占 $0.300576，事务提交后才发送；拿到匹配版本的有效 usage 后按未缓存价格保守结算并释放多余预占。当前短句的实际费用通常远低于预占，但不以猜测的 Token 数授权支付。并发请求共享 PostgreSQL 事务锁 / SQLite 写事务；余额不足以覆盖上界时提前拒绝。

超时、供应商错误、响应丢失或用量缺失均保留预占。同一请求编号再次提交只读原记录，不自动再次支付；进程中断也不自动过期释放。更换模型、移除连接、保存设置、重启均不重置额度。页面显示已结算、预占和剩余；无页面重置或提高额度入口。设置页新增持久化验证历史和逐请求人工核对：登记满 5 分钟、用量仍未确认的请求，研究者确认供应商请求已经结束后，填写实际输入/输出 Token、供应商记录编号及核对依据；后端串行结算、保留原记录与审计，相同请求防重，已结算记录不可改写。人工核对依赖供应商证据和研究者准确输入，不能当作清空额度；无法确认时保留预占。该上限仅覆盖本部署按上述核对价格发起的 API 使用费，不限制相同密钥在其他应用的消费或账户税费；官方价格变化前需要重新核对。后续 Advisor 的每个准备/工具/回复模型请求也必须经过此账本，不能另开直连路径。

连接成功仅确认认证与文本请求可用，不等同于流式、工具、取消能力或完整 Advisor 验收；真实实验发放继续关闭。

## 已实现的选择边界

- 设置页可维护多个独立模型连接，含稳定 ID、显示名称、接口地址、模型名、独立 API Key。没有模型也能保存设置和正常开发联调。
- 发码页为整批统一选择一个模型；默认 modelId=null，继续确定性发码。实验条件和模型选择是独立配置，Neutral/Goal 两组可共用同一批选择。
- 选择连接后，预览将接口、模型名及加密凭据保存为私有不可变工件，并把引用冻结到安排配置。后续编辑或移除注册项不会改写原预览；密钥不进入参与者 DTO 或管理预览响应。
- 旧版单模型设置读取时自动迁移为一个注册项，不丢失已有加密凭据。
- 当前真实执行器未就绪：真实模型预览返回 runtimeMode=agent、canIssue=false；界面提供预览，后端阻止发放。确定性配置返回 canIssue=true。不能把选择真实模型的实验静默改成确定性回复。

## 第一阶段：真实调用的独立验证

新增供应商适配层，统一消息、流事件、函数工具、供应商请求 ID、使用量与失败状态。首先明确每个连接的协议和能力，不能仅凭 Base URL 推断兼容性，也不能把填写了模型名视为验证通过。

先在独立沙盒中检验一个供应商、一个模型、一个案例：连接、认证、流式回复、工具参数、取消及超时。配置由冻结工件解析，凭据只在服务端解密。已有 Key 被供应商撤销时应记录真实失败；不自动切到其他 Key、模型或确定性回复。

当前已提供固定短句的 OpenAI 连接验证及预算账本。待完成：流式事件、工具参数、取消及完整案例沙盒；连接验证结果不提前宣称这些能力通过。

## 第二阶段：接入完整研究 Advisor

在同一 Advisor 中实现每轮 prepare → 允许的资料工具 → select_strategy → 正式 reply。策略提交成功后再进入正式回复，正式回复阶段关闭工具；准备文本不展示给参与者。不额外调用一个“策略模型”，不生成伪造思维过程。

构造上下文时只读取冻结的公开案例、选项顺序、动作目录，以及当前 attempt 的真实对话/工具历史。Goal 才包含固定目标；Neutral 不发送后台比较目标。Profile、初始/最终判断和研究者 Notes 不进入模型输入。

记录真实模型配置引用、供应商请求/响应 ID、工具参数与结果、策略、使用量、耗时、失败和可获得的供应商原生摘要。未返回的字段明确记为缺失，不事后生成推理记录。

产物：真实 Advisor 执行器及上下文白名单、工具、策略提交、正式输出过滤的集成测试。仅有普通聊天回复还不足以开放研究实验发放。

## 第三阶段：接入现有实验闭环并开放发放

保留 HTTP 受理和 SSE 公共快照，让 Worker 按冻结配置选择确定性执行器或真实 Advisor。真实调用在数据库事务外执行；领取作业、持有租约、保存检查点与提交结果使用短事务。Session.runtimeMode 从实际执行配置产生，替换当前硬编码的 deterministic。

真实运行不能沿用确定性 Worker 的三步重算恢复：

- 同一消息重复提交不创建第二个运行。供应商是否受理不明时先核对已有运行，不能直接再次发送；不能声称应用层实现了第三方调用的严格恰好一次。
- 刷新、断线后观察原运行；部分回复按相同消息 ID 更新。供应商失败、超时和预算耗尽保留真实状态与部分文本。
- 放弃或取消后，迟到结果只关联旧 attempt，不能推进新任务。写入核验 job、attempt、turn 和当前执行权。
- 保留最少 3 轮、默认最多 20 轮；完整回复保存成功后再计数和推进最终判断。
- 加入每轮 Token/工具/耗时预算与供应商并发限制，拒绝无提示切模型或协议降级。队列扩展可以后续接 Redis/Celery，业务与记录源仍为数据库。

在真实能力验证、完整 Advisor 和流程恢复验收通过后，才开放对应模型的 canIssue。开放后只影响新预览、新发放；已有安排保持其原配置。

## 验收顺序

1. 离线适配器桩测试上下文隔离、工具协议、幂等、超时、取消及迟到响应，不消耗真实额度。
2. 独立沙盒小样本验证真实供应商事件和失败方式；确认策略与工具记录可回放。
3. 在参与者 HTTP/SSE 流程中验证刷新恢复、排队、3/20 轮边界与最终判断；管理回放不调用模型。
4. 明确案例审核目标、正式 Prompt/ToolBox、模型能力及预算后开放研究批次。上线仍单独验收 PostgreSQL、部署和备份恢复。

这项接入主要新增执行器和运行恢复逻辑，可复用现有发码、授权、Profile、测量、任务页、SSE 和回放页面。具体工作量取决于首个供应商协议、工具能力和取消/回查能力；先做独立沙盒可以较早暴露这些差异。
