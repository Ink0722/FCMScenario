# 阅读层级与刷新保护技术记录

日期：2026-10-18。界面版本：0.5.0。

## 范围

按用户补充要求保持 58:42 两栏比例。本轮整理阅读层级、字体和操作反馈，并保护刷新时的未提交输入。没有新增英文案例、翻译 PDF、改写金融事实、重设计 Profile 题项或接入后端。

## 阅读与操作

- 共同条件使用有序列表，编号只标识段落位置，正文、顺序、金额、限制和选项保持。章节标题以字重和字号区别于正文，继续保留连续文档布局。
- 文件标题使用轻下划线，右侧明确显示 Open PDF；可展开的术语带原生折叠标记和点状下划线。没有为每段重新增加边框。
- 提交按钮跟随表单，长题时表单区域可收缩滚动，操作按钮保持可见；两栏各自滚动，58:42 不变。
- End conversation 从开始就显示，由 Gateway 返回的 canEnd、probeRequired 及请求状态决定能否操作。静态提示说明通往最终判断以及开始阶段暂不可结束，没有轮数倒计时、质量评分或“凑轮数”提示。
- 确认结束时若有未发送消息，明确说明会舍弃；取消保留内容，确认成功后清除对应草稿。

## 字体

使用项目内的 Source Sans 3 正文字体和 Source Serif 4 标题字体，英文字体文件固定，数字采用等宽数字特性；中文仍使用系统回退。字号集中在 CSS 变量中，区分展示标题、页面标题、材料标题、章节、正文、操作和辅助文本。

文件来自 Adobe 官方 Source Sans／Source Serif 仓库，原始 WOFF2 未改动。许可证和字体 SHA-256／源 blob 标识保存在 public/fonts/。页面预加载并从同站点提供字体，不请求外部字体服务；不同系统仍可能有抗锯齿等渲染差异。

## 草稿机制

草稿单独存于当前标签页 sessionStorage 的 fcm.draft.v1 命名空间，不属于正式作答，也不会自动发送给 Gateway 或 Agent。

| 输入 | 隔离范围 | 恢复匹配 |
| --- | --- | --- |
| 初始、中途、最终判断及置信度 | session ID + pre/probe/post | 案例与共享文案 revision |
| 未发送消息及待确认请求 ID | session ID | 同一材料 revision |
| Profile 未提交答案 | 规范化 participant code | 题项配置 |

编辑时同步写入，避免紧接着刷新丢失最后一次输入。刷新只恢复当前阶段，不从初始判断复制答案到最终判断。空白、越界和小数数值草稿不被自动改正，提交时继续按原规则检查 0–100 整数。

提交成功才清除对应草稿，失败保留。明确确认返回任务列表后清除该未完成会话的全部草稿，取消不清除；Profile 返回确认只清除未提交问卷；完成任务清除会话草稿。已提交 Profile 和已完成任务仍按原规则保留。

恢复时使用 Gateway 返回的进度对照草稿，已接受的判断不重新显示为待提交，消息按请求 ID 判断是否已经接收；不按相同文字去重，保留用户主动重复发送的能力。过期 24 小时、版本不符、未来时间或损坏的记录不恢复。存储失败不会阻止填写和提交，会显示当前输入无法留存的提示。

## 实现位置

- src/app/drafts.ts：草稿校验、隔离、清除和提交状态核对。
- src/app/useDraft.ts、DraftStatus.tsx：同步写入、恢复提示和存储失败反馈。
- src/access/useAccess.ts、storage.ts：Profile 页面刷新恢复及返回清除。
- src/experiment/state/useExperiment.ts：成功提交、消息请求和完成时的清除。
- DecisionPanel、DialogueScreen、ProfileForm：对应输入控件。
- public/fonts/：字体原件、许可证、来源及校验记录。

## 边界

草稿只保护同标签页刷新，无法替代正式结果持久化、跨设备恢复或已关闭标签页恢复。草稿写入失败与 Gateway 接收失败分别处理；现有本地 Mock 也使用 sessionStorage，不能据此宣称整个应用在完全禁用存储时仍可运行。现有本地 Gateway 和原有接口契约保持；真实后端仍按原计划后续接入。
