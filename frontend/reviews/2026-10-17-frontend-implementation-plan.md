# 前端实施方案：轻微绿色调与英文实验界面

日期：2026-10-17。本文保留原实施计划。界面及交互修改已完成，最终配色按用户后续要求进一步减少绿色，并加入极淡水蓝与暖白；执行范围和验证结果见同目录 `2026-10-17-frontend-implementation-result.md`。案例、Profile 题项及后台未在本轮修改。

## 1. 目标与范围

建立浅色、略偏绿色、以材料阅读和作答为中心的桌面界面。用户可以替换现有淡黄与深红配色，不要求延续 FinTrace 或人大视觉。保持现有 React、Vite、状态机及 ExperimentGateway 分层，不引入新的 UI 框架。

本轮实施：视觉系统、页面排版、固定界面英文化、交互中性化、无默认值的置信度输入、可访问性、前端契约整理和验证。

保留：自由选择案例；开始后锁定当前任务；返回任务列表时确认并清除该任务未完成进度；已提交 Profile 与已完成任务保留；Profile 作为列表最上方的独立任务，每个测试编码填写一次；阅读与初始判断合并；初始判断、交流、最终判断均可查看材料。

边界：不编写或改变 case、金融材料、PDF、选项语义和评分；不重新设计 Profile 题项；不实现真实后台、隐藏条件分配、真实 AI 或持久化服务；不增加手机端布局。不擅自新增正式问卷、同意条款和研究说明内容。

## 2. 视觉系统

以下是设计起始值，需经过对比度与页面检查；不是文献证明的最优色值。

| 角色 | 起始值 | 使用范围 |
| --- | --- | --- |
| 页面背景 | #F4F7F5 | 极浅灰绿，主要体现于页面边缘及入口背景 |
| 内容表面 | #FFFFFF | 材料、表格、输入框与作答区 |
| 次级表面 | #EDF3EF | 轻量分区与表头，不整页铺绿 |
| 正文 | #24312B | 深灰，保持高对比 |
| 次要文字 | #5F6D65 | 辅助说明；不使用过淡灰字 |
| 主操作 | #315B48 | 开始、提交等主按钮 |
| 主操作悬停 | #274A3A | 鼠标反馈 |
| 完成状态 | #28704C / #EDF7EF | Completed、完成勾选与感谢提示 |
| 选项选中态 | 石墨灰边框与极浅灰底 | 不使用成功绿或红绿对比表达决策选项 |
| 错误 | 独立暗红色 | 仅用于校验、请求失败等错误 |

所有颜色整理为语义变量，区分主操作、选中、完成、错误和焦点，清理 CSS 内散落的旧红色与米黄色。

排版使用系统无衬线英文字体栈，不加载外部字体。英文正文先按 16px、1.55–1.65 行高试排；界面控件以 14px 为主；主标题 20–24px；辅助文字通常不小于 12px。数字使用等宽数字特性。间距以 4/8/12/16/24px 组织；圆角 4–6px；以细分隔线区分区域，只在弹窗等必要位置使用阴影。统一中性的文档线性图标与 favicon，不添加机构徽章、人像、闪电或人格化装饰。

## 3. 页面与流程

默认流程：Participant code → Study tasks → Background questionnaire（该编码首次）→ Study tasks → Initial choice（同时阅读材料）→ Conversation（按现有策略可出现 Current choice）→ Final choice → 完成提交 → Task complete → Study tasks。

Profile 已完成时直接跳过资料步骤。最终判断保存成功后才完成；保存、完成请求失败时停留可重试状态，不显示虚假的成功提示。

### 编码入口

- 同一淡灰绿背景，紧凑页面标题，不做大幅宣传式首屏。
- 桌面采用说明与编码表单并列，完整实验说明可阅读，输入框和 Continue 容易找到。
- 保留加载、无效编码、网络错误、重试状态；不把网络错误描述为编码无效。
- 验证成功后进入任务列表；前端不向参与者显示开发用编码列表、处理条件或内部标识。

### 任务选择

- 顶部显示 Study tasks、当前 Participant code 和已完成任务数。
- 实验说明继续可查看，采用紧凑说明区；折叠时仍有明确标题和入口，首次入口说明完整提供。
- Background questionnaire 独立置顶；只重做容器和界面标签，正式题项由用户后续提供。
- 任务采用紧凑列表：选择控件、任务编号、任务名称、状态。保留自由选择，不增加推荐、难度或星级。
- 支持至少 20 个任务，列表自然滚动，操作栏在底部保持易于访问；留出底部空间，避免遮住最后一行。无须逐个制作页面，不强加分页或搜索。
- 无默认选中任务；完成项显示绿色勾选和 Completed，不再显示可选单选框。未开放项使用独立说明，不与全部完成共用一条消息。
- 明确区分：全部完成、暂时无可开始任务、尚未安排任务、请求失败。

### 实验工作区

- 顶栏约 52–56px，与整体背景协调。左侧为简短研究名称与 Back to tasks，阶段导航右对齐。
- 任务编号保留在材料栏头部；材料内部导航继续向右对齐。阶段导航和材料导航是两套不同导航。
- 沿用约 58:42 双栏，允许小幅调节比例以容纳英文；材料与右栏分别滚动，操作区保持可见。
- 决策题干位于右栏，左侧不重复展示实验说明；任务材料、补充信息和原文入口均保持可访问。
- 表格和单元格继续居中，A/B 列宽对称；长英文自动换行，不通过缩小字体挤满首屏，不突出某一选项的收益或风险。
- 不改变材料的事实、条款、顺序和解释，不自动生成概要或结论。

### 初始、当前与最终判断

- 三个时点复用同一 DecisionPanel，选项样式、置信度题干及端点一致；无默认选项，不显示历史答案作为提示。
- 将空白数值框作为置信度主输入，范围 0–100、只接受整数，0 与 100 都合法。
- 初版移除带可见默认位置的滑杆；若保留滑杆作为后续辅助控件，必须解决未填写态与首次取值，不以 0 或 50 的滑块暗示已经作答。
- 只在缺少输入或校验失败时给出具体提示，不评价决策质量。
- 保存中禁止重复提交，失败保留当前输入；正式量表解释沿用经确认的共享内容，不自行改变测量含义。

### 对话与结束

- 沿用 AI assistant / You 的中性角色标签，不增加专家身份、头像或拟人化动画。
- 用户与助手可用排列、标签和细边界区分；文本阅读区保持白色，避免助手大面积绿色底。
- 结束交流按钮在满足现有策略后明确可见，与 Send 使用相近尺寸，不用文案推动多聊或少聊。
- 结束确认框只说明会进入 Final choice 且不能回到对话；去掉鼓励继续交流的额外理由。
- 保留当前中测触发协议；本轮不擅自改变轮数、随机规则或新增倒计时。

### 返回、保存与完成

- Back to tasks 返回任务选择页，不返回编码输入页。
- 未完成任务需确认：本次任务的作答与对话进度会清除；已提交资料及已完成任务保留。取消后继续原状态。
- 完成页显示简短感谢与 Back to tasks，绿色仅表示提交完成；数据保存完成后才使用 saved 字样。
- 当前最终判断后直接进入完成流程。未来若提供正式后测或 Debrief，再在最终判断与完成之间按协议接入；本轮不创建空白页面，不虚构后测，不提前宣称完成正式研究流程。

## 4. 英文化边界

固定 UI 全部英文化：页面标题、导航、按钮、状态、加载、错误、弹窗、键盘提示、无障碍标签、浏览器标题与 document lang。正式会话不提供临时语言切换。

建立集中式英文文案资源，区分固定 UI 文案与从材料/接口加载的内容。固定文案使用 Participant code、Study tasks、Background questionnaire、Initial choice、Conversation、Final choice、Back to tasks、Completed 等统一术语。

Profile 题项、共享测量题干、案例正文、资料 PDF、AI 回复均是独立内容来源。只英文化界面不能称为完整英文实验。对现存中文材料和题项列出内容清单，由相应内容负责人提供或确认译稿；本轮不自动改写 case 和 Profile，不通过实时机器翻译改变材料。检查长标题、长错误提示、日期与数字格式。

## 5. 实验一致性与接口

- 所有处理条件共享同一布局、颜色、图标、提示和错误反馈，不显示隐藏目标、内部策略或条件标签。
- 前端不按回复内容渲染推荐色、风险色或身份徽章；不把某种风格描述为能消除全部内生性。
- 保留 ExperimentGateway 接口边界；整理 Mock 和未来 HTTP 适配的替换入口，前端业务组件不直接绑定网络地址。
- 保留 verifyTestCode、getTasks、getParticipantProfile、submitProfile、startTask、submitDecision、sendMessage、endDialogue、abandonTask、completeSession 等现有能力，不实现服务端。
- UI 版本、语言与文案版本应可识别；本轮形成一个固定的桌面英文视觉版本，避免核心采集期间混用主题。
- 比较表的列头与数据按相同 option.id 映射读取，修复表头遍历 options 但表体固定 A/B 的潜在错配；本轮保持现有顺序，不擅自随机化。若将来由后台提供顺序，同一会话各时点与材料保持一致。
- 记录阶段呈现、提交、结束与请求错误等必要前端事件；不把打开文档当作已经读懂，不根据切换标签判定违规。不暗中改变用户要求的清除规则或保留被声明清除的答案。
- 原文阅读器属于后续独立增强：本轮先保证现有原文入口可发现且状态一致，不为视觉调整引入大型 PDF 渲染依赖。

## 7. 验收

- 桌面 1366×768、1440×900、1920×1080，常见缩放下查看；保留可访问滚动和操作，不宣称支持手机端。
- 键盘能完成编码、选任务、作答与弹窗；焦点可见，弹窗取消后合理返回焦点，状态变化可被辅助技术识别。
- 普通正文对比度至少达到 WCAG AA 4.5:1；检查控件与焦点对比度，不只依赖颜色表达状态。
- 测试 0/1/20 项任务、长英文题名、Profile 未完成/完成、全部完成、暂无可用、空列表及请求失败。
- 测试置信度空值、0、100、非法值；三个测量时点无默认值；选项表头与数据始终一致。
- 测试未填禁用、提交中重复点击、失败重试、最终保存失败不提前完成；返回取消保留当前状态，确认后按现有规则清除并回任务列表。
- 检查英文固定 UI 无遗漏；明确区分仍待译审的材料内容，不把中文内容的存在隐藏为已完成英文化。
- 执行现有单元测试、适当补充有行为价值的用例、构建和端到端检查；无需为纯色值和间距增加实现镜像测试。
- 真人 Pilot 作为正式采集前的后续验证：检查阅读理解、误操作、字号与主观可信度；不凭开发测试声称已证明没有视觉影响。

## 8. 证据与解释边界

- Tuch et al. (2012)：较低视觉复杂度和熟悉布局与更好的第一印象美感有关，不直接证明提高金融判断质量。https://research.google/pubs/the-role-of-visual-complexity-and-prototypicality-regarding-first-impression-of-websites-working-towards-understanding-aesthetic-judgments/
- Robins & Holmes (2008)：相同内容的视觉精致程度可能影响可信度判断。https://www.sciencedirect.com/science/article/pii/S0306457307000568
- Piepenbrock et al. (2014)：校对任务支持浅底深字，不能据此证明特定绿色或黄色最优。https://journals.sagepub.com/doi/10.1177/0018720813515509
- de Visser et al. (2016)：拟人化可能改变对建议代理的信任韧性；并非现代大模型任务的直接证据。https://pubmed.ncbi.nlm.nih.gov/27505048/
- WCAG 2.2 正文最低对比度规范属于可访问性要求，不是配色偏好的实验证据。https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html

本方案的绿色调来自用户偏好；低装饰、清晰阅读、跨组一致来自对研究目标与已有证据的综合设计判断。
