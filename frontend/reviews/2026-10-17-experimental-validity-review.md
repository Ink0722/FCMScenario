# 前端实验有效性审查与英文版建议

审查日期：2026-10-17。代码基线：`3f99ccb047daaa84191deb0935f30100edeb379a`。范围为 Notion「结构」及其可访问子页、现有前端源码、共享测量说明、现有截图，以及案例 01 的材料和 PDF 排版源文件。用户确认英文版主要面向英语熟练或以英语为主的受试者。

本文件是审查意见，不是已经实施的修改。本轮没有改动应用、金融材料、问卷或 Notion。未逐份重审 42 份 PDF 的金融事实、计算及法律适用性，也未开展真人 Pilot。

**总体判断**

现有页面有合适的实验骨架：固定原始材料、桌面双栏、A/B 对称、三个时点复用测量组件、不预填选择和置信度、不持续展示历史判断、不展示 Agent 的内部策略。主要问题在实验流程与数据边界，而不是视觉风格。正式采集前应优先解决自由选题、退出删除记录、顺序随机化、置信度起始线索，以及基线/后测/知情同意的完整流程。

不能通过前端“完全消除内生性”。需要分别处理随机分配与失访选择、测量反应性、需求效应、信息获取差异、版本和数据恢复。全组相同的 UI 不必然是混杂，但可能改变实验情境或与处理交互；同样，对话长度和阅读行为可能是处理的结果，不能为了“控制变量”而默认在主分析中调整。

研究目标应继续围绕随机给予 Agent 隐藏目标的总体效应。自主选择的具体策略与用户反应之间，仍主要是观察性关联，而非仅靠 UI 就能识别的策略因果效果。[研究问题与实验设计](https://app.notion.com/p/3f63854bbee9803bb028d6d934a8e95f)、[5. Experiment](https://app.notion.com/p/3f73854bbee98016b6f5ce2071a6c1ef)。

**正式采集前优先修改**

1. **系统分配案例，避免让“选题”成为未设计的实验环节。**

   当前 [TaskSelectionScreen](../src/access/TaskSelectionScreen.tsx) 允许自由选择所有可用任务，题名也会提前暴露后续内容。对熟悉金融或某类产品的人，选择与任务表现可能相关；多任务还会引入学习、疲劳和警觉。

   自选发生在不知道条件之前，并且条件在所选案例内严格随机、两组分配平衡时，并不必然破坏组间处理效应识别；但结果对应的是自选样本，不能等同于系统分配总体。为减少解释负担，主实验建议系统分配一个案例；多案例扩展保持参与者的条件不变，并平衡顺序、考虑重复观测相关性。列表仍可保留资料任务、已完成项和当前分配项。

   正式参与代码应不含 Neutral、Goal、Probe 等条件线索，并与稳定的参与者身份绑定。开发用共享代码不等于一人一码；同一人重新登录、凭证更新或换码不能重新抽取条件、重做基线或清除已有任务状态。Profile 按稳定 participant_id 归属；若代码只是入口凭据，不能把“每个代码一次”误当成“每个人一次”。

2. **退出改为暂停/退出研究，不再把已经暴露过的任务“清空重来”。**

   [useAccess](../src/access/useAccess.ts) 的返回流程调用 `abandonTask`；[本地接口实现](../src/integration/mock.ts) 删除会话内容，释放锁并允许新开一次。这样会丢失条件相关的中断、重试和重复暴露，后续只看成功完成记录可能产生选择偏差。

   正式模式中，普通“返回列表”保留同一 episode、条件、顺序、已提交决策及对话，之后继续同一任务。单独设置自愿退出研究的流程，按已批准的同意与撤回规则处理数据；不得以防偏差为由阻止退出，也不能无条件保留依法或依同意条款应删除的数据。未完成、异常中断及允许保留的尝试记录需要可审计；缺失结果不能直接当作已观测结果补进分析。

3. **真正实现 A/B 显示顺序，并同时固定资料与作答的映射。**

   当前 `Session` 没有显示顺序字段。尤其需要注意：[ScenarioPanel](../src/experiment/components/ScenarioPanel.tsx) 的表头按 `s.options` 渲染，表体却固定渲染 `row.A`、`row.B`。只打乱 options 会把列头和实际内容错配。

   服务端为 episode 确定稳定的选项身份和显示顺序。资料列、卡片、单选项在 Pre/Probe/Post 使用同一映射，刷新也不变。PDF 内的产品类别名称不能随界面位置任意改写；若额外重新命名显示 A/B，需要事先冻结完整映射与计分规则。目标和正确答案继续留在服务端，不让客户端自行分组或推算。

4. **消除“未填写但看起来在 0”的置信度线索。**

   [DecisionPanel](../src/experiment/components/DecisionPanel.tsx) 的数据初值确实为 `null`，这点正确。但 range 使用 `confidence ?? 0`，未触碰时仍有位于低端的灰色滑块，并在首次 `pointerdown` 把当前值写入状态。键盘方向键也从 0 开始。

   建议以空白数值框作为明确输入，滑杆仅作辅助；首次明确选值前不展示一个已经落在 0、50 或 100 的滑块。首次点击应取参与者实际指向的位置，不先赋 0。保留 0、100 两个合法端点和同一套量表解释。这里是可能的测量线索，不声称已在当前样本中实证证明锚定效应；需通过 Pilot 检查分布与操作错误。

5. **保留前置 Profile，但换成能回答研究问题的正式基线测量。**

   当前 [questionnaire/config.ts](../src/questionnaire/config.ts) 只有阅读设备和 AI 使用频率，尚不能支撑 Financial Background 的异质性分析。前置每人一次的结构可以保留；需冻结金融知识/投资经验、AI Experience 的定义、题项、计分与缺失规则。

   基线中不放“AI 是否在操纵你”“你会不会被说服”等提示假设的问题。知识题不在任务前反馈答案或提供与该案例直接相关的解题训练。若担心基线提问引起警觉，应在 Pilot 检查，不能一边需要处理前调节变量、一边事后随意改为处理后测量。后台 Profile、Pre 和 Probe 回答默认不提供给 Agent；Agent 仅使用协议允许的信息及自然对话中透露的内容。

6. **补齐最终判断后的测量、知情同意和研究说明。**

   当前 [App](../src/app/App.tsx) 在最终判断保存后直接完成；未包含独立的 Consent、Post-test 和 Debrief 页面。这不只是问卷位置调整。

   建议补充：正式任务前的知情同意；最终判断后的理解、信任、目的猜测或操纵觉察测量；最后按批准方案进行研究说明、联系与退出处理。顺序坚持 Behavior First, Reflection Later。后测失败或操纵检查失败不能事后作为随意删样本依据。测量本身可能改变后续行为，这是需要评估的风险，而非所有检查都必须取消。[Hauser et al., 2018](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2018.00998/full)。

**随后应改进的呈现与交互**

7. **让完整材料容易查看，同时不替参与者解题。**

   以[案例 01](../../cases/01_Fund_Shares/material.md)为例，网页主表只列识别代码，费用及主要条款在招募说明书中。这不能简单判断为“遗漏费用”，因为 PDF 属于完整材料；问题是 [参考链接](../src/experiment/components/ScenarioPanel.tsx) 目前另开标签页，文档访问和阅读技能可能成为额外负担。

   建议在现有材料栏内增加原文文档阅读入口，保持阅读器、默认缩放、文档标签和返回方式一致，并允许对照全部相关资料。记录文档打开、呈现时间及必要的页面暴露事件，但“打开了”不等于“读过并理解”。不要强制滚到底来证明阅读，也不要为追求首屏信息量自动提炼结论或突出决定答案的数字。PDF 页眉的“仅供模拟使用”、网页说明及 Consent 应统一为准确的研究情境说明，而不是让不同阅读路径得到不同的任务真实性提示。

8. **结束交流的控件与文案不主动鼓励多聊或少聊。**

   当前发送按钮比结束按钮更突出，[结束确认框](../src/experiment/components/EndDialog.tsx) 又先提示“如果还有想了解的内容，可以继续交流”。这不是必然的组间混杂，但可能改变停止行为及处理剂量。

   达到统一最低轮数后，两个动作都应容易发现；确认框只说明将进入最终判断、不能回到对话，不再追加继续交流的理由。统一最低/最高轮数、时间与失败规则，并记录真实停止原因。不要为了控制混杂，把自然对话全部截成相同长度；也不要默认把实际轮数、阅读次数或策略选择作为主效应回归的普通控制变量。现行研究章将这些视为处理后的过程变量，这一判断应保留。

9. **中测作为测量干预管理。**

   [Mock policy](../src/integration/mock.ts) 只演示固定 2 轮中测、3 轮后可结束，并没有正式随机 K、统一上限或超时协议。不能将其误认为实验规则已落实。

   如果主问题只是最终影响，取消中测是可考虑的最小干扰版本；如果必须研究过程变化，则按方案随机 K，在所有条件中使用相同协议，且中测最迟不晚于最早可结束时点。现有内嵌、暂停输入、提交后收起且不显示历史答案的方式可以保留。随机 K 不能消除中测本身的反应性；有需要时在独立 Pilot 或预设的有/无中测条件中检验。

10. **人文关怀保留在合适位置，完成色不等于答对色。**

    登录前 Welcome、所有最终测量后的 Thank you、清楚的帮助与退出说明都可以保留。不要在核心决策前或每轮之间加入“你的判断很专业”“相信自己的第一直觉”“再仔细想一想”等带评价、承诺或努力指向的提示。普通礼貌不自动等于操纵策略，但应作为跨组一致的固定文案冻结。研究者需求信念可能影响行为，具体影响大小需要测量，不能从语气直接推定。[de Quidt et al., 2018](https://www.aeaweb.org/articles?id=10.1257/aer.20171330)。

    浅暖黄、深红主题、中性阅读图标和绿色“已完成”可以保留，不需要全部推倒。绿色只表示资料/步骤提交成功，不用于显示财务选项正确、风险较低或更值得选择。不要引入真实机构的权威徽章、评级或“专业顾问”身份强化。

11. **补齐过程记录，并固定 UI 版本。**

    当前事件类型只有 stage_view、reference_open、information_toggle、dialogue_end；实际页面修改后仍沿用静态 `uiVersion: '0.2.0'`。对于后续自然响应、停止行为和模拟受试者校准，这些还不够。

    最少应有稳定 participant/episode/attempt 标识、案例顺序、选项顺序、测量和语言版本、材料版本、阶段时间、回复实际呈现完成时间、用户提交时间、文档打开、页面可见性、暂停/退出原因、错误及重试记录。AI 生成时间不能直接替代受试者实际看到回复的时间；看文档切标签页也不应直接当作离开实验。记录按[数据规范](https://app.notion.com/p/3e93854bbee981bc8a91f69032d8fff7)分层；隐藏 Goal、策略工具与后台画像不需要因此暴露给前端。主分析和描述性过程分析分开。

12. **明确外部信息和辅助工具的边界。**

    实验设计页允许参与者自行获取外部信息，并称 Agent 与人具有相同权限；Agent Prompt 又限定只使用 Scenario 与对话。这两种协议不能同时用来声称已经消除信息差。共同可访问材料也不代表双方实际获取或理解了相同信息。

    为使主实验较容易解释，建议以给定材料为事实边界，统一说明能否使用计算器、外部网页或其他 AI；需要的中性辅助工具对两组相同。若有意研究开放信息环境，则另行冻结双方权限、信息来源记录及分析边界。普通前端无法证明没有在另一设备使用外部工具；标签页离焦只能记录为可见性变化，不能直接据此认定违规或事后删样本。不要在治疗后按阅读次数或外部信息使用与否随意筛选主分析样本。

**英文版本**

建议本轮正式采集使用一个锁定的英文版本，面向英语熟练者，而不是在任务中提供实时中英切换。可以保留另一个独立的中文开发/Pilot 版本，但不要未经设计就把两种语言的数据混在一起。无需只招母语者；记录与招募相关的英语熟练程度及必要的金融制度熟悉度。

英文化至少包括 UI、共享题干、案例正文、术语、Profile、后测、Consent/Debrief、加载和错误提示、无障碍标签、页签以及资料 PDF。抽查的案例 01 PDF 排版源文件为中文，不能把现有资料都视为已是英文原文；现有 42 份参与者 PDF 需要逐份盘点。金融合同的日期、辖区、币种、金额、资格、例外及计费口径不能因翻译而改为另一套产品规则。

用固定译稿与术语表，逐项核对数字和条件，独立复核易歧义表达，再做英语受试者 Pilot。回译可以辅助，但不替代金融语义、任务理解、量表和版式验证。ITC 的适配指南强调题干意义、作答格式/尺度与目标人群适用性，并要求通过试测检查，而非只做逐句翻译。[ITC 指南](https://www.intestcom.org/files/guideline_test_adaptation_2ed.pdf)。

“Confidence”继续表示对所选方案的确定程度，不改成盈利概率，也不改成仅适用于有标准答案案例的“Probability that your answer is correct”。不要对所有案例统一宣称“没有正确或错误答案”，因为 Type I 确有事前评价依据。页面语言、材料译本、问卷、Agent 输入/输出语言与 locale 分别版本化；同一参与者的 Pre/Probe/Post 保持一致。英文版字体和行高应重新做桌面阅读检查，不直接照搬中文字号而假定阅读负担相同。

**推荐流程与修改顺序**

参与代码 → 知情同意与必要的设备/语言检查 → 任务目录（一次性基线资料置顶）→ 系统分配案例 → 材料与前测 → 隐藏条件按协议激活 → 自然对话（可选随机中测）→ 最终判断 → 后测 → Debrief → 完成与感谢。

保留现有双栏和大部分组件。先冻结实验口径、分配与暂停恢复，再做全英文材料和正式问卷；最后统一交互、文案和版本，开展 Pilot。若继续以 signed-confidence ADS 为主要终点，仍需验证其解释和跨人可比性；更换 UI 控件不会自动解决量表问题。可预设 Target Choice、Choice Switching 与 Type I Accuracy 作为不同层次的行为结果，不把它们等同于某个心理机制已经发生。
