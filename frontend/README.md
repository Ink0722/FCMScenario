# 金融决策实验前端

桌面端实验前端，参与者界面按正式任务呈现，不包含预览设置、模拟回复提示或占位文案。全部场景复用现有 canonical 材料。按当前开发约定，后端仍待接入：本地由 Mock 驱动编码校验、任务分配、回复和流程，已提交进度保存在当前浏览器标签页的 `sessionStorage`，刷新可以恢复；不是服务端持久化。

## 启动

需要 Python 3 和 Node.js 22.12+。项目使用 React + TypeScript + Vite。

```bash
cd frontend
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。首先输入测试编码，验证后进入任务选择页，标题右侧显示已验证的当前测试编码和测试任务完成数量。用户资料作为独立任务固定在所有测试任务上方，未提交时显示「待填写」及「填写资料」按钮；提交后返回列表并标记「已完成」。填写前可以查看分配的测试任务，但不能开始。用户资料按测试编码保存一次，同一编码再次验证、刷新或退出任务后仍显示已完成；完成状态使用绿色底色、绿色文字及勾号，与待填写、待开始和暂时不能开始区分；不同编码分别填写。资料填写页返回列表时会提示未提交内容不会保存，取消保留当前输入，确认后可以从列表重新打开填写。刷新未提交的资料页会回到任务列表。必须明确选择任务并点击「开始测试」，即使只有一个任务也不自动开始。开始前可以更换选择或编码；测试期间固定任务，刷新、重新打开首页或改变 URL 参数都会恢复同一任务。点击「返回主界面」则弹窗提示当前进度不会保存：取消或按 Escape 继续当前测试，确认后丢弃未完成任务的作答与消息记录，保留已验证的编码并回到任务选择页。刷新仍停留在选择页，可以重新选择原任务从头开始，也可以选择其他可用任务。已完成任务的结果保留；完成后可以返回任务列表开始其他任务，已完成任务不可重复开始。全部完成时显示感谢与作答已保存提示，隐藏开始按钮和重复的实验说明；仅暂时没有可开始任务时单独说明安排，不显示全部完成。

任务的内部 `id`、参与者可见的 `number` 和材料 `case_id` 分开维护。例如 `TASK-7K3M` 是任务编号，`01` 仅用于当前材料映射；界面不以「场景 01」作为任务编号。一个材料可以用于不同测试任务，正式编号和分配将由后端提供。前端不读取 `case`、`probe` 等 URL 参数分配任务。

本地检查编码仅配置在 Mock 中，参与者界面不公开这些编码：

| 编码 | 分配 |
| --- | --- |
| `FCM-2026` | 三个任务：`TASK-7K3M`、`TASK-4P8R`、`TASK-9C2N`（内部材料 01、09、17） |
| `FCM-SINGLE` | 单个任务（内部材料 02） |
| `FCM-PROBE` | 启用中途判断的 `TASK-2X9Q`（内部材料 01） |
| `FCM-ALL` | 全部 20 个任务，供材料检查 |
| `FCM-EMPTY` | 未分配任务 |
| `FCM-EXPIRED` | 过期提示 |

其他编码返回无效提示。Mock 编码忽略首尾空格和大小写，验证凭证有效期为 24 小时；正式规则由后端决定。开发时如需重置当前标签页，在浏览器控制台删除 `sessionStorage` 的 `fcm.access.v1` 与 `fcm.mock-service.v2` 后刷新。只删除入口缓存不会解除 Mock 中已开始的任务。

默认不启用 Probe；开启时在第 2 次完成消息交换后显示，Mock 在第 3 次完成消息交换后允许结束交流。参与者界面不显示轮数。

入口流程：测试编码 → 任务选择（用户资料任务置顶）→ 用户资料（每个编码一次）→ 返回列表选择测试任务。任务流程：阅读与初始判断 → 交流（可插入 Probe）→ 最终判断 → 完成。阅读和初始判断合并成一个阶段，直接完成判断后进入交流。最终判断保存后自动完成任务；完成请求失败时可以重试，刷新会从已保存的最终判断继续完成，不需重复作答。

Pre、Dialogue、Post 共用桌面双栏，左侧持续显示背景、共同条件、A/B 资料、全部补充条款、PDF 和背景知识，决策任务统一放在右侧。两栏独立滚动；Pre/Post 的确认按钮固定在右栏底部。公共实验说明在编码入口和任务选择页展示，场景页直接从任务材料开始。页面采用最小宽度 1100px 的桌面布局，不提供手机端重排。

页签与顶部共用 `public/decision-mark.svg` 深红阅读图标，浏览器主题色使用页面暖色。界面使用深红、浅暖黄色背景与接近白色的内容面板，A/B 方案的视觉样式对称。顶部使用与页面相同的暖色背景，高度 57px；名称和返回按钮在左，01—04 阶段靠右，任务编号位于材料栏标题处（完成页放在内容标题处，独立用户资料页不显示任务编号）。材料与作答栏宽度为 58:42，正文约 15px、1.6 倍行高。材料栏的章节按钮只定位本栏内容，不改变任务、阶段或已填写答案。表格水平及垂直居中，置信度滑杆与数值输入并排；编码入口、任务列表和问卷沿用同一套紧凑样式。样式重排不改写 canonical 材料或测量题意。

初始判断、中途判断和最终判断均需独立填写 A/B 与整数置信度，不继承历史作答。置信度不预填，0 和 100 都是有效值。当前问卷仍使用两道开发阶段题目，正式 Profile 测量内容待确定，参与者页面不显示示例或占位标签。

## 材料

`npm run dev` 和 `npm run build` 会先执行 `scripts/prepare_materials.py`。它复用 `tools/materials.py` 校验并读取源文件，只将参与者材料和对应 PDF 复制到 `public/materials/`；Notes、研究者答案、来源底稿及原始源文件路径不进入材料包。

生成器从同一份 `shared/instructions.md` 额外导出 `instructions.json`，只包含公共说明 `welcome` 和 `revision`。编码验证前仅加载这份公开说明；验证后的任务查询及开始流程才加载场景快照。两个入口页共用同一说明组件，加载失败时可以重试。将来由 `getExperimentInstructions` 接入公开说明接口，不需要开放任务材料。

PDF 文件名使用内容 SHA-256，JSON 快照同时覆盖材料、共享文案和 PDF 版本。开始任务时冻结材料与共享文案，恢复任务使用原始快照，不自动更新、不根据对话改写。生成器不覆盖不同版本的 PDF 或快照，避免影响已打开会话。

修改材料后运行 `npm run materials`，再刷新页面开始新任务；已开始任务继续使用原版本。检查同一任务的新材料时，先按上述方法重置标签页存储。开发期间不监听材料并强制刷新，因为这会中断实验。生成目录与 `dist/` 不纳入 Git，不手工编辑。将来发布时须同时管理资源的版本保留期限。

## 代码结构

- `src/app/`：入口、统一布局、阶段进度和全局样式。
- `src/access/`：编码输入、独立用户资料、任务选择、开始前后的入口状态及刷新恢复。
- `src/content/`：材料类型与快照加载。
- `src/experiment/flow/`：阶段和对话状态转换的纯函数。
- `src/experiment/state/`：异步操作、重复提交锁、消息失败恢复及请求标识。
- `src/experiment/components/`：共享材料栏、右栏决策任务、统一决策组件和结束确认框。
- `src/experiment/screens/`：Pre/Post 共用的双栏判断页，以及双栏对话页。
- `src/questionnaire/`：配置化问卷；正式题目待补充。
- `src/integration/`：服务约定、Mock 及真实服务的预留入口。

入口状态：`code → tasks`；列表中的用户资料任务进入 `profile`，提交或确认返回后回到 `tasks`；资料完成后允许 `tasks → active`。实验状态：`pre → dialogue → post → finishing → complete`；`finishing` 仅表示最终判断已保存、正在确认完成，不是额外参与者步骤，失败可重试；`pre` 同时承担阅读。对话子状态：`ready / waiting / probe / confirm`。等待回复和 Probe 期间禁用消息输入；结束交流只能从允许结束的 `ready` 状态进入确认，再转到 Post。

## 后端接入边界

`src/integration/contracts.ts` 定义应用需要的服务方法；没有假定具体 HTTP 路径。`http.ts` 是明确的未接入占位，不发送任何请求。后续实现 `ExperimentGateway` 后，在 `App.tsx` 替换 Mock 工厂即可复用页面和流程。

预留操作：

| 操作 | 用途 |
| --- | --- |
| `getExperimentInstructions` | 获取编码入口与任务选择页使用的公开实验说明及版本 |
| `verifyTestCode` | 校验分发编码，返回访问凭证、有效期及用于界面显示的 `testCode` |
| `getAccessGrant` | 凭访问凭证恢复已验证的编码信息，兼容旧缓存不含显示编码的情况 |
| `getTasks` | 获取该凭证可访问的任务编号、标题和状态 |
| `startTask` | 校验分配与任务锁，创建或返回会话，冻结材料版本 |
| `resumeTask` | 验证会话归属，恢复同一任务、材料、阶段及已提交进度 |
| `abandonTask` | 确认返回主界面后丢弃未完成任务的进度，释放任务锁；已完成结果保留 |
| `sendMessage` | 提交消息，接收 AI 回复和最新的结束/Probe 状态 |
| `submitDecision` | 分别保存 Pre、Probe、Post 的选择与置信度 |
| `endDialogue` | 后端确认交流可以结束 |
| `getParticipantProfile` / `submitProfile` | 凭验证凭证获取用户资料题目及提交状态，按编码身份保存一次；不传任务会话编号 |
| `recordEvent` | 阶段、PDF 打开、背景知识展开和主动结束事件 |
| `completeSession` | 确认结果已保存，返回完成凭证 |

`getTasks` 只返回任务元数据；`startTask` / `resumeTask` 返回 `StartedTask`，包括任务、会话、冻结的 Scenario / SharedCopy、材料包版本和 `SessionProgress`。后者包含阶段、对话状态、消息、各次判断和完成凭证；用户资料独立于 `SessionProgress`，按编码归属保存。正在进行的任务会直接恢复，不再展示选择页。未提交的输入不属于已保存进度。

后端负责编码真实性与有效期、凭证及会话归属、任务分配、已开始任务锁、已完成任务限制、真实轮数、随机化、隐藏 Goal、Agent、持久化和幂等校验。`requestId` 支持开始和提交重试，`Message.id` 支持消息重试；同一请求不得创建多次会话。HTTP 实现须为所有会话操作附带验证后的访问凭证，并在服务端校验，不能只依赖前端按钮或浏览器存储。界面只显示验证返回的测试编码，不把访问凭证当作编码。刷新时重新验证访问凭证并恢复 `testCode`。当前静态材料/PDF 可以被直接访问；正式访问控制需由后端或资源服务实现。

退出操作同样需服务端校验会话归属与完成状态，并保证幂等。前端等待 `abandonTask` 成功后才清除缓存中的会话标识，保留验证凭证并重新获取任务列表；退出失败时保留当前任务并在确认框显示错误。如果退出成功但列表加载失败，可重试或刷新恢复任务选择页。Mock 仅保留退出会话的标识及归属用于幂等，丢弃其作答、交流和事件记录，保留编码层面的用户资料，旧开始请求不能恢复或重新创建已退出会话。完成会话不会被退出操作删除。用户资料归属应使用稳定的编码或参与者标识，不能用短期访问凭证或任务会话作为资料主键。Mock 按规范化编码保存资料，即使凭证过期重新验证也沿用同一份资料。旧版本地任务中已提交的问卷迁移为编码资料，旧问卷阶段迁移为完成确认阶段。以上仍是前端接入约定，没有实现真实后端。

前端只消费参与者所需信息和 `canEnd / probeRequired` 状态。参与者资料与决策通过专用方法保存，不放进 `sendMessage` 的请求中。前端不传入或指定场景、Probe 和其他实验条件；正式服务应使用后端分配的任务、会话和材料版本。

未来接入时还需确定编码生成和分发规则、身份标识、Consent/Post-test/Debrief 内容、正式问卷、服务端错误格式、流式消息、超时及跨设备恢复规则。当前没有实现编码管理后台或真实后端。
